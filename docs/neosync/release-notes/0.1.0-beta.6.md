# NeoSync 0.1.0-beta.6

Minecraft **1.21.1**, NeoForge **21.1.252**, Java **21**. Install matching
NeoSync versions on the client and dedicated server. HTTPS discovery uses
capability protocol 1; explicitly selected HTTP uses protocol 2. The manifest
schema remains version 1.

## Changes since beta.5

- A selected mod JAR can now describe NeoForge mods bundled through a declared
  JarJar archive. The server associates those mods with their containing file in
  the manifest, including their versions and client dependencies. For example,
  Create 6.0.10 bundles Flywheel and Ponder; selecting the Create JAR represents
  all three mods as one downloadable file.
- The client checks the nested archive metadata against the approved manifest
  before preparing the profile. Archive inspection remains bounded and does not
  load classes. Undeclared nested JARs and unsupported loader arrangements are
  rejected.

This fixes a NeoSync discovery startup failure where Create's required Flywheel
dependency was missing from the manifest even though the server loaded it from
Create's JarJar archive. The failed publication left clients without a NeoSync
discovery advertisement, so NeoForge proceeded to its missing-channel rejection.

## Installation

Download the same installer for clients and dedicated servers. Existing
installations do not update themselves.

```sh
java -jar NeoSync-0.1.0-beta.6-neoforge-21.1.252-installer.jar
```

For a dedicated server in a new directory:

```sh
java -jar NeoSync-0.1.0-beta.6-neoforge-21.1.252-installer.jar --install-server ./neosync-server
```

Select only files that clients need. Exact Modrinth matching or an explicitly
configured direct HTTPS source remains required; bundling dependencies does not
authorize other download sources. HTTP manifest mode still requires the server's
advertised port to be reachable and the player's explicit confirmation.

## Validation and limits

The [Linux build](https://github.com/enderliker/NeoSync/actions/runs/36338833090),
[Windows build](https://github.com/enderliker/NeoSync/actions/runs/36338833116),
and [release packaging](https://github.com/enderliker/NeoSync/actions/runs/36338865256)
passed on source commit `7b3a4b071a2c505ea16f074b8280e4cbdfc2468b`.
Both platforms built the project, checked formatting, and ran unit tests with
Java 21. Windows installed and started a dedicated server; the release workflow
installed and started both client and server on Linux. Local Linux validation
passed 255 unit tests and archive checks.

A local server installed from the beta.6 installer loaded the real Create 6.0.10
JAR with `resolveProviders:true`, advertised NeoSync over Minecraft status, and
served one hash-verified manifest entry containing Create, Flywheel, and Ponder.
Its source resolved to an exact Modrinth HTTPS artifact. The synthetic HTTP
profile test downloaded and verified one containing JAR after consent.

A real Azure-to-Prism download, restart, and join remain pending.
The local server test used HTTP on loopback; it does not validate the remote
server's public port or TLS configuration. This change covers declared, bounded
NeoForge JarJar archives, not arbitrary nested archives or every mod combination.
macOS remains unvalidated. The published installer has SHA-256
`1766b9399c1721b8955957d09edc3271e1854c97b265d7040b985e9a41664793`.
The five JARs are listed in `release-manifest.json`; `SHA256SUMS` covers those
JARs and the manifest itself.

## Artifacts

The prerelease contains installer, universal, sources, earlydisplay and matching
earlydisplay-sources JARs, `SHA256SUMS`, and `release-manifest.json`. Generated
Minecraft JARs, installations, test mods, worlds, accounts, and credentials are
