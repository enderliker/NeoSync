# NeoSync 0.1.0-alpha.2 — NeoForge 21.1.251

This alpha uses NeoSync's geometric N throughout the installer, launcher profile,
startup graphics, mod list, and repository. The title screen shows the NeoSync
version alongside the NeoForge base. Upstream licenses and contributor notices
remain intact; mod compatibility still uses NeoForge 21.1.251.

**Minecraft Java Edition 1.21.1 · Java 21 · NeoSync 0.1.0-alpha.2 · Protocol 1**

Download **`NeoSync-0.1.0-alpha.2-neoforge-21.1.251-installer.jar`** for the client
or dedicated server. Client and server must both use alpha.2; alpha.1 profiles
are not silently upgraded. The previously published alpha.1 remains unchanged.

For a client, run the installer with Java 21, choose **Install client**, and select
the generated NeoSync version in your launcher. For a dedicated server:

```sh
java -jar NeoSync-0.1.0-alpha.2-neoforge-21.1.251-installer.jar --install-server /path/to/server
```

Start the server with its generated `run.sh` or `run.bat`. Review and accept the
Minecraft EULA yourself if you agree. Configure synchronization using the
[setup guide](https://github.com/enderliker/NeoSync/blob/NeoSync-0.1.0-alpha.2-neoforge-21.1.251/docs/neosync/phase-3.md#server-configuration-and-manual-activation).

The installer includes the runtime and the startup graphics library. The separate
`-universal.jar` and `-earlydisplay.jar` are for tooling and inspection, not files
to put in `mods`. Their matching `-sources.jar` and `-earlydisplay-sources.jar`
provide corresponding sources. `SHA256SUMS` and `release-manifest.json` record
artifact integrity and the source commit. Minecraft game JARs are not bundled.

## Validation

- All 187 unit tests and formatting checks passed.
- The exact installer passed client and dedicated-server installation and startup
  on Linux with JDK 21.0.2. Both installations extracted the startup library from
  the installer and validated its checksum.
- Graphical inspection confirmed the startup N, mod-list banner, and title-screen
  versions. A runtime probe verified the icon bytes and loaded library location.
- A fresh one-mod flow passed both consent cancellations, verified HTTPS download,
  isolated preparation, manual activation, restart, and a real server join with
  Clumps 19.0.0.1 using the repository's production launcher harness.
- Package validation checks each replacement image, library coordinates, embedded
  bytes, and matching sources. All FML classes, sources, service registrations,
  module metadata, and other unchanged content match the pinned upstream archives.
- Negative probes rejected modified FML code, stale startup graphics, an upstream
  replacement URL, and a missing source-license file.

## Known limits

This remains an experimental MVP. Manual profile activation and restart are
required, and no external launcher is certified. Automatic provider resolution,
browser-assisted manual imports, server hosting, and automatic restart remain
unimplemented. Windows and macOS runtime validation is outstanding.

Development runs still resolve the original FML dependency; inspect startup
branding with an installed build or the production launcher harness. Hash checks
do not establish mod trust, and profile isolation is not an execution sandbox.
See the [Phase 3 record](https://github.com/enderliker/NeoSync/blob/NeoSync-0.1.0-alpha.2-neoforge-21.1.251/docs/neosync/phase-3.md)
for broader validation limits.
