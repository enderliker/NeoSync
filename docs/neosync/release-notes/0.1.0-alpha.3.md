# NeoSync 0.1.0-alpha.3 — NeoForge 21.1.251

This alpha adds restricted server hosting for mods written by the administrator
specifically for that server and not published or distributed elsewhere. Hosting
is disabled by default. Administrators must declare authorship, exclusivity and
distribution rights for each file's exact SHA-256 before it can be served.

**Minecraft Java Edition 1.21.1 · Java 21 · NeoSync 0.1.0-alpha.3 · Protocol 1**

Download **`NeoSync-0.1.0-alpha.3-neoforge-21.1.251-installer.jar`** for either the
client or dedicated server. Both sides must use alpha.3. Existing alpha.1/alpha.2
profiles are not silently upgraded, and their published releases remain unchanged.
NeoForge mod dependency checks continue to see base version **21.1.251**.

## Install and configure

For a client, run the installer with Java 21, choose **Install client**, and select
the generated NeoSync version in your launcher. For a dedicated server:

```sh
java -jar NeoSync-0.1.0-alpha.3-neoforge-21.1.251-installer.jar --install-server /path/to/server
```

Start the generated `run.sh` or `run.bat`. Review and accept Minecraft's EULA
yourself if you agree. Configure HTTPS and explicitly select client files using
the [hosting setup guide](https://github.com/enderliker/NeoSync/blob/NeoSync-0.1.0-alpha.3-neoforge-21.1.251/docs/neosync/phase-4.md#server-configuration).
Configured external HTTPS downloads remain supported.

## Changes

- The server copies and verifies eligible files into a bounded snapshot before
  advertising them. Changing a live file in `mods` does not change that snapshot.
- Full downloads resolve only published hashes on the server's HTTPS origin.
  Request, connection, transfer, bandwidth, disk and time limits bound the service;
  paths outside the inventory, ranges and request bodies are rejected.
- Client review and the additional warning identify the server as the source.
  Both consent screens default to **No, cancel**. Downloads require explicit
  acceptance of the displayed files and sources.
- Hosted downloads retain TLS identity, exact size/SHA-256 and JAR checks. An
  approved LAN endpoint does not authorize external LAN URLs or hosted redirects.
- Verified files are prepared in an isolated revision. Manual activation and a
  restart apply the mod set; failed or canceled operations preserve prior profiles.

Hosting is **public** and does not inherit Minecraft authentication, whitelists or
bans. Eligibility declarations do not independently prove authorship. General
redistribution permission, provider outages and author download restrictions do
not make third-party files eligible for hosting.

## Assets and integrity

The installer embeds NeoSync's runtime and startup graphics library. Separate
`-universal.jar` and `-earlydisplay.jar` files are for tooling and inspection, not
mods to place in `mods`. Matching `-sources.jar` and `-earlydisplay-sources.jar`
retain corresponding sources and upstream notices.

`SHA256SUMS` covers the five JARs and `release-manifest.json`. The manifest records
the source commit, versions, sizes and SHA-256 hashes. Generated Minecraft game
JARs, test mods, worlds, installations and credentials are not release assets.

## Validation

The following results were recorded on September 22, 2026 for the exact installer
above, on Linux x86-64 (CachyOS) with JDK 21.0.2:

- All **197 unit/integration tests** and formatting checks passed.
- Client and dedicated-server installation and startup passed using new disposable
  directories. Package checks verified embedded bytes, isolated paths, branding,
  matching sources and preserved FML code and notices.
- A generated administrator-authored mod with no external source completed both
  consent cancellations, explicit acceptance, hosted download, isolated preparation,
  manual restart, startup verification and a real dedicated-server join. The
  final graphical check waited for the loading screen to close and the world to
  render with the expected mod loaded.
- The installed server rejected a third-party hosting selection despite declared
  redistribution rights, without leaving a discovery advertisement, file listener
  or hosted snapshot.
- Installed-service probes verified TLS certificate/hostname rejection, restricted
  routes and unchanged snapshot bytes after modification of the live mod file.
- An intentional exit 73 during profile publication preserved the previous pointer.
  Relaunching that previous revision verified it and joined the server again.
  This was a process-interruption check, not a power-loss test.
- Service/client tests covered quotas, symlinks, ambiguous HTTP framing,
  disconnect/retry, corrupted downloads, cancellation and prior-profile preservation.

Release preparation rechecked artifact integrity and correspondence with those
validated bytes; it does not count the earlier runs as new runtime executions.
See the [Phase 4 evidence](https://github.com/enderliker/NeoSync/blob/NeoSync-0.1.0-alpha.3-neoforge-21.1.251/docs/neosync/phase-4.md#installed-build-acceptance)
for the exact environment, coverage and limitations.

## Known limits

This is an experimental prerelease. Validation covers one minimal top-level
javafml mod and the repository's production launcher harness. Windows, macOS,
external launchers, public reverse proxies, large modpacks and sustained load
remain unvalidated. Narrator audio was unavailable because the test system lacked
`libflite`.

Automatic provider resolution (including CurseForge), browser imports, private
authenticated distribution, range/resume and automatic restart remain unimplemented.
Profile isolation is not an execution sandbox; mods retain Minecraft's permissions.
Startup profile verification occurs after FML loads mods. HTTPS and matching hashes
do not establish that a mod is trustworthy.
