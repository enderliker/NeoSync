# NeoSync 0.1.0-alpha.4 — NeoForge 21.1.251

This prerelease adds exact Modrinth source resolution and a consented browser
import flow for server-reported restricted CurseForge files. CurseForge metadata
queries use an administrator-owned key on the server. The distributed client and
installer contain no provider key.

**Minecraft Java Edition 1.21.1 · Java 21 · NeoSync 0.1.0-alpha.4 · Protocol 1**

Download **`NeoSync-0.1.0-alpha.4-neoforge-21.1.251-installer.jar`** for either
the client or dedicated server. Both sides must use alpha.4. NeoForge mod
dependency checks continue to see base version **21.1.251**.

## Install and configure

For a client, run the installer with Java 21, choose **Install client**, and select
the generated NeoSync version in your launcher. For a dedicated server:

```sh
java -jar NeoSync-0.1.0-alpha.4-neoforge-21.1.251-installer.jar --install-server /path/to/server
```

Start the generated `run.sh` or `run.bat`. Review and accept Minecraft's EULA
yourself if you agree. Configure HTTPS and explicitly select client files as
described in the [server setup](https://github.com/enderliker/NeoSync/blob/NeoSync-0.1.0-alpha.4-neoforge-21.1.251/docs/neosync/phase-2.md#server-setup) and
[Phase 5 source guide](https://github.com/enderliker/NeoSync/blob/NeoSync-0.1.0-alpha.4-neoforge-21.1.251/docs/neosync/phase-5.md#provider-identity-and-protocol-compatibility).
The server can resolve existing selected JAR bytes through Modrinth without
provider IDs or a key. Configured direct HTTPS sources and eligible restricted
server hosting remain available.

For a file unavailable through Modrinth, the administrator may configure exact
CurseForge project/file IDs and set their **own** `NEOSYNC_CURSEFORGE_API_KEY` in
the server process environment. The key must stay out of server configuration,
logs, manifests, client environments and release assets. Without it, the server
reports the missing setting and does not advertise an incomplete provider
inventory. Users never supply a key. Administrators must ensure their applicable
provider agreement permits this use and retained metadata.

## Source handling and consent

- Modrinth lookup matches the existing server file by SHA-512. Before review,
  the client checks the exact provider version, file URL, size, Minecraft version
  and NeoForge loader. Downloaded bytes must match the approved manifest SHA-256
  and provider SHA-512.
- The server queries CurseForge only when Modrinth has no exact match and exact
  CurseForge IDs were configured. The client receives only the bounded file
  identity, reported SHA-1, selected URL and manual-download status. Its review
  says that these values came from the server and keeps the unverified-source
  warning. The client does not independently verify CurseForge metadata.
- When the server reports third-party downloads disabled, acceptance opens the
  exact official `/download/<fileId>` page. NeoSync watches the configured
  Downloads folder or accepts an explicitly selected file, checks the approved
  hashes and JAR metadata, and prepares an isolated profile. The website may
  require further interaction.
- Installation review and the additional unverified-source warning both default
  to **No, cancel**. A changed file, source or hash requires fresh consent. No
  third-party file is hosted by the server to bypass a provider or author rule.

Profiles still require manual activation and restarting Minecraft. Failed or
canceled preparation preserves the active installation.

## Assets and integrity

The installer embeds NeoSync's universal JAR and matching startup graphics
library. Separate universal and earlydisplay JARs are for inspection, not mods to
put in `mods`; their matching sources retain attribution and licenses.
`SHA256SUMS` covers the five JARs and `release-manifest.json`. Generated Minecraft
game JARs, installed directories, test mods, worlds and credentials are not
release assets.

## Validation

On Linux x86-64 with JDK 21.0.2, formatting and all 246 JUnit tests passed
with no failures, errors or skips. The exact installer passed package checks,
installed a client and dedicated server, and passed both production startup
self-tests. The first client install timed out downloading a NeoForged Maven
dependency; retrying completed successfully with checksum validation.

With the final installed build, a live Modrinth lookup for Clumps 19.0.0.1 led
through both default-negative consent screens, exact download verification,
isolated preparation, a fresh client process and a real dedicated-server join.
A separate synthetic CurseForge manual-import fixture exercised the exact
`/download/<fileId>` page, relocated Linux Downloads watching, verified import,
restart and real-server join. It used a fixture-only server setting and made no
CurseForge API request. A server using a newly generated mod with no Modrinth
match and no CurseForge key reported the required administrator setting and left
discovery disabled. Screenshots and acceptance reports were inspected. See the
[Phase 5 record](https://github.com/enderliker/NeoSync/blob/NeoSync-0.1.0-alpha.4-neoforge-21.1.251/docs/neosync/phase-5.md#alpha4-release-candidate-validation-on-september-23-2026)
for exact paths and scope.

## Known limits

Phase 5 is not complete. No real CurseForge key or author-restricted website flow
was available for this release's validation. Current third-party API terms need
an applicable permission or clarification for retaining provider metadata in
manifests and local audits. The server-reported CurseForge identity is not an
independent client verification or a malware-safety guarantee. Automatic restart,
external launcher certification and Windows runtime acceptance are pending.
Profile isolation is not an execution sandbox: mods run with Minecraft's
permissions. Startup profile verification occurs after FML loads mods.

See the [Phase 5 record](https://github.com/enderliker/NeoSync/blob/NeoSync-0.1.0-alpha.4-neoforge-21.1.251/docs/neosync/phase-5.md) for exact implementation details, recorded
runs and remaining acceptance blockers.
