# NeoSync 0.1.0-beta.8 candidate

Minecraft **1.21.1**, NeoForge **21.1.256**, Java **21**. Install matching
NeoSync versions on the client and dedicated server. HTTPS discovery uses
capability protocol 1; explicitly selected HTTP uses protocol 2. The manifest
schema remains version 1.

This is an unpublished candidate. The existing beta.7 release and earlier
artifacts retain their existing identities and bytes. Final source identity,
checksums and CI results will be recorded before release review.

## Changes

- Authorized builds include CurseForge API access in the client and dedicated
  server runtime. Automatic resolution still checks exact Modrinth matches first,
  then CurseForge. Requests use fresh metadata; API-derived IDs, URLs and hashes
  are excluded from manifests, profiles and consent records. Missing access,
  restrictions or provider failures do not authorize alternate versions or
  third-party hosting.
- Credential packaging rejects enabled Gradle build and configuration caches.
  Explicit release validation checks the masked runtime access against the private
  input, checks nested installer archives, and rejects literal keys or access in
  source archives. Rebuilding without a key removes access from the runtime and
  installer. Forks must obtain their own key.
- Modrinth App preparation completes the Minecraft client, runtime libraries,
  assets and logging files before registering an instance as ready. Corrupt official
  resources are repaired through verified staging, with rollback preserving the
  prior bytes on failure. Modified local NeoSync files remain rejected. Server
  revision preparation verifies the runtime and preserves paths containing spaces.
- The graphical installer selects supported launchers or a custom directory and
  prepares their runtime without user scripts. Windows packaging embeds the same
  installer JAR in an EXE and checks its identity during extraction. **Accept all**
  accepts the reviewed file set; separate source confirmation remains required.

## Installation

After this candidate is published, use the same installer for clients and
dedicated servers:

```sh
java -jar NeoSync-0.1.0-beta.8-neoforge-21.1.256-installer.jar
```

The Windows `-installer.exe` opens the same GUI using installed Java 21. The
wrapper is unsigned. For a dedicated server in a separate directory:

```sh
java -jar NeoSync-0.1.0-beta.8-neoforge-21.1.256-installer.jar --install-server ./neosync-server
```

Select only files needed by clients in the administrator panel and restart the
server to publish the selection. Users review the exact files and sources before
downloads. Follow the [launcher guide](../launchers.md) for selecting and launching
prepared installations.

## Validation and remaining platform checks

Local Windows validation on October 9, 2026 achieved:

- 291 runtime unit tests passed. Ten historical symbolic-link test methods were
  excluded from this local Windows run; those methods still require CI validation.
- 20 installer tests and eight Python release-validator tests passed.
- Installed credential-bearing client and dedicated-server startup self-tests
  passed. These establish runtime startup, not a multiplayer installation flow.
- A live authenticated CurseForge request returned HTTP 200. Exact fingerprint
  lookup matched the Clumps 19.0.0.1 artifact; this check did not install it.
- The candidate Windows wrapper passed its extraction, Java discovery and
  installer self-test with the exact embedded JAR.

The explicit installed CurseForge fixture passed default-negative review and
source-consent cancellation without creating a store, then accepted and downloaded
Clumps 19.0.0.1, verified its bytes, prepared an isolated profile, restarted, and
joined a real loopback dedicated server with Clumps loaded. This used CurseForge
live lookup and download rather than automatic Modrinth selection.

The automatic Modrinth installation and repeat verification passed for beta.8
on Windows. All runtime resources and the assets index were verified offline;
the instance is registered as `installed` with Minecraft protocol 767 and displays
**Play** in the library. Actual launch and native server-revision join remain
pending; installed state alone does not establish gameplay compatibility.
Linux and Windows CI, the final source commit, final installer/EXE
verification and exported checksums are pending. macOS and remote Azure-to-Prism
acceptance remain unvalidated.

## CurseForge notice and artifacts

On October 9, 2026 the NeoSync owner supplied CurseForge's confirmation that
public NeoSync client/server builds may embed the recoverable key and that forks
must apply for their own key. Masking is not secure secret storage.

Use of NeoSync's CurseForge API functionality is subject to the
[CurseForge 3rd Party API Terms and Conditions](https://support.curseforge.com/en/support/solutions/articles/9000207405).
An API key embedded in an authorized NeoSync build does not grant permission to
reuse or redistribute that key. Forks and third-party distributions must obtain
their own applicable authorization and apply for their own key.

Planned review assets are installer, universal, sources, earlydisplay and matching
earlydisplay-sources JARs, the Windows installer EXE, `SHA256SUMS`, and
`release-manifest.json`. Only the authorized runtime contains masked provider
access. Source archives, private credential files, generated Minecraft JARs,
installed game directories, test mods, worlds, accounts and TLS identities are
excluded.
